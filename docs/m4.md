# M4 — Interactive study sessions

Interactive study uses a durable queue on top of M3's FSRS-7 scheduler.

```sh
node index.ts study
node index.ts study 1
node index.ts study 1 --new-limit 10 --review-limit 50
node index.ts study --new
node index.ts study --all
node index.ts study --resume
node index.ts study 1 --restart
```

On a real terminal, press **Space or Enter** to reveal the answer, then rate it with a single key: **1 Again, 2 Hard, 3 Good, 4 Easy**. Press **s** to skip, **u** to undo the last session review, and **q** to quit without losing the queue. Piped input accepts one command per line.

By default, the queue contains currently due reviews and new cards, with reviews first (oldest due first). `--new` selects only new cards; `--all` selects all cards including those not due, **and records actual FSRS reviews**. A new session allows up to 20 new cards and 100 reviews; set `--new-limit` or `--review-limit` to customize (0–1000). Set either to 0 to disable that kind.

An interrupted session is preserved. Repeat the **same command** to resume it, or use `study --resume` without other flags. To discard an unfinished queue and create a new one, use `--restart`. Skipped cards remain eligible for future sessions. There is a single active session per local database.

**Crash consistency:** SQLite schema version 3 persists the selection, queue status and review-event IDs. The FSRS review and queue completion commit atomically. A second rating of the same queued item and reviews by another process are detected rather than silently double-recorded. Undo appends a compensating FSRS event.

If you modify cards outside a session while it is open, a queued card may become stale. Skip that card or restart the session. M5 will add typing and cram modes; `--all` in M4 is **not** cram because it updates FSRS scheduling.

See [M3 scheduler documentation](m3.md) for the FSRS state model.
